# 분석·생성 알고리즘

로컬 Python 서버(`server/rhythm_server`)가 곡을 분석하고 채보를 만든다. 모든 단계는 numpy·scipy만 쓴다.

## 1. 표준 오디오

업로드된 파일을 PyAV(FFmpeg)로 한 번 디코딩해 44.1kHz 스테레오 16bit FLAC(`audio.flac`)로 저장한다. 분석과 브라우저 재생이 **같은 PCM**을 쓰므로, MP3 인코더 딜레이처럼 디코더마다 다른 앞부분 지연이 채보를 밀어내지 못한다.

## 2. 분석 (`analysis/`)

| 단계 | 방법 | 합성 음원 기준 정확도 |
|---|---|---|
| 온셋 | 멜 스펙트럼(1024/256)의 SuperFlux식 플럭스(주파수 최대값 필터, 2프레임 지연)를 저·중·고역으로 나눠 피크 검출, 포물선 보간으로 프레임 이하 정밀도. 강한 온셋 직후의 약한 같은 대역 피크(킥 피치 스윕·감쇠)는 마스킹 | 재현율 0.82–1.0, 타이밍 편향 중앙값 ±1ms 이내 |
| 템포 단계 | 온셋 함수 자기상관 + 지각 사전분포(135 BPM 중심), 박 단계 후보(½·1·2배) 비교 | — |
| 고정 BPM 그리드 | 강약 가중 빗살 템플릿(정박 1, 8분 0.45, 16분 0.2)을 전곡 온셋에 맞춰 BPM(0.0002 단위)과 위상을 거친→세밀 탐색. 킥·베이스 비중을 높여 오프비트 하이햇이 위상을 빼앗지 못하게 함 | 곡 전체 그리드 오차 최대 1.4ms (목표 10ms) |
| 템포 변화 | 24박 창마다 지역 BPM을 구해 전체와 1.2% 넘게 다르면 구간 분할 → 경계는 양쪽 그리드 잔차가 최소인 지점으로 보정 → 구간별 재피팅 | 120→150 BPM 곡 최대 1.3ms |
| 다운비트·박자 | 박마다 저역 타격·화성 변화(크로마 신규성)·스네어 억제 단서를 모아 4/4·3/4와 마디 위상을 고름 | 다운비트 일치 100% |
| 음높이 | 온셋에서 새로 커진 화성 성분 중 멜로디 대역(200–2000Hz) 최강 부분음 → 하위 배음 확인 | 반음 이내 50–55%, 윤곽 상관 0.64 |
| 지속음(롱노트 후보) | HPSS 화성 성분에서 그 음의 배음만 추적, -10dB로 떨어지거나 다른 온셋이 다시 칠 때 종료 | 긴 음 끝점 오차 중앙값 25ms |
| 곡 구조 | 박 동기 멜·크로마·온셋 활동량 → 자기유사 행렬 → Foote 신규성(32박 커널)으로 마디 경계 → 구간 평균 특징으로 반복 묶음, 에너지로 후렴 표시 | 절·후렴 교대를 A/B로 정확히 묶음 |

4분 곡 기본 분석은 약 15초(4코어 CPU)다.

## 3. 생성 (`generator/`)

1. **파라미터**: `config/difficulty.json` 프리셋(평균·피크 NPS, 허용 분할, 최대 동치, 롱노트 비율, 연타 최소 간격, 손 제약, 스크래치·사이드 비율)을 키 모드 보정값과 함께 적용. 목표 레벨을 고르면 해당 프리셋 안에서 보간. 그 위에 **스타일**(아래 표)의 배율을 곱하고, 마지막으로 사용자가 직접 지정한 값(밀도 0.5–1.5배, 롱노트 비율 0–50%, 최대 동시 노트 프리셋+1까지, 스크래치·사이드 비율 0–20%, 리듬 기준)이 이긴다. 한계값은 `overrideLimits`.
2. **양자화**: 온셋을 허용 분할 그리드에 스냅. 단순한 리듬부터 시도(4분 → 8분 → 16분 → 셋잇단 → 32분)하고, 스냅 오차가 35ms 또는 분할 간격의 30%를 넘으면 버린다. 같은 그리드 점에 모인 온셋은 합친다.
3. **후보 점수**: `강도^0.7 × 박자 위치 가중치 × 대역 가중치(난이도별 고역 비중) × (0.55 + 0.9 × 국소 강도) × 리듬 소스 가중치`. 국소 강도는 음량과 온셋 활동량을 8박으로 평활한 값.
4. **밀도 제어**: 목표 노트 수(평균 NPS × 실제 소리가 있는 시간)를 점수 순으로 채우되, 1초 창 피크 NPS와 부분 허용 분할 비율을 지킨다. 활동 중인 마디가 비지 않도록 바닥값을 둔다. **없는 소리에는 노트를 만들지 않는다.**
5. **동치·롱노트·스크래치·사이드**: 여러 대역이 동시에 강한 타격에 동치(키 수가 적으면 더 드물게), 지속음이 충분히 긴 음에 롱노트(끝점도 그리드 스냅), 저역+고역 임팩트에 스크래치. 사이드 트랙(FX)은 DJMAX처럼 패드·스트링·긴 보컬 같은 **서스테인 소리 위 롱노트가 60%**(1박 이상, 4분·8분 위치, 그 슬롯의 건반 롱노트는 탭으로 바뀜)이고 나머지는 강한 타격 탭이다. 최소 450ms 간격을 두고, 저역이 강하면 왼쪽·고역이 강하면 오른쪽 사이드에 놓는다. 롱노트를 잡은 손의 사이드 입력은 손 제약(`holdHandLimit`, `maxHoldsPerHand`)을 그대로 따른다.
6. **레인 배치(빔 서치, 폭 5)**: 키 모드별 손가락 모델(`config/keymodes.json`의 손·손가락)로 하드 제약(같은 레인 연타 간격, 롱노트 뒤 간격, 손당 동시 입력, 롱노트를 잡은 손의 추가 입력, 손당 롱노트 수)을 지키면서 비용을 최소화한다.
   - 음높이가 높을수록 오른쪽, 멜로디 상승·하강은 같은 방향 이동(계단), 같은 음 반복은 같은 레인(연타)
   - 음이 다른데 같은 레인 반복은 감점, 빠른 구간은 양손 교대, 레인 사용량 균형
   - 시드 기반 소량의 잡음으로 패턴 다양성(같은 시드 = 같은 채보)
7. **난이도 루프**: 산정한 레벨이 목표 범위의 가운데에 오도록 밀도를 조절해 다시 생성(최대 5회). 동치·연타 때문에 레벨이 높게 나와도 프리셋 최소 밀도의 80% 아래로는 줄이지 않아, 난이도가 오를수록 노트 수가 늘어난다. 후보를 다 써도 목표에 못 미치면 강한 타격을 동치로 두껍게 만들고, 그래도 부족하면 `densityLimited`로 표시한다.
8. **린터**: 레인 범위, 시각, 중복, 롱노트 겹침·간격, 연타 간격, 동치 수, 손 제약, 손당 롱노트 수를 검사한다. 위반이 하나라도 있으면 채보를 내보내지 않는다.

### 스타일 (`config/difficulty.json`의 `styles`)

스타일은 프리셋을 바꾸는 배율과, 후보 점수·레인 비용의 가중치다. 소리가 없는 곳에 노트를 만들지 않는 규칙은 그대로라서, 곡에 없는 리듬(예: 16분이 없는 곡의 스트림)을 억지로 만들지는 않는다.

| 스타일 | 주요 조정 | 7K+1S HARD 측정(합성 128 BPM, 시드 42) |
|---|---|---|
| 균형 | 프리셋 그대로 | stream 0.09 · chord 0.36 · jack 0.12 · LN 0.27 |
| 스트림 | 동치 ×0.45, 8분·16분 후보 가중, 같은 레인 반복·같은 손 연속 비용 ↑ | stream 0.35, chord 0.18 |
| 동치 | 동치 ×1.8, 최대 동치 +1, 다운비트 가중 | chord 0.65 |
| 연타 | 연타 최소 간격 ×0.75, 400ms 안의 같은 레인 반복에 보너스 | jack 1.00 |
| 롱노트 | 롱노트 ×2.4, 최소 길이 ×0.6, 화성적 소리 가중 | LN 0.71 (롱노트 28 → 90개) |
| 테크니컬 | 셋잇단·16분·32분과 엇박 후보 가중, 부분 분할 한도 ×1.8 | technical 0.40 |
| 멜로디 | 화성적·음높이 있는 소리 가중, 음높이 → 레인 위치·윤곽 비용 ↑ | 음높이 순서대로 배치 |

## 4. 난이도 산정 (`difficulty/estimator.py`)

osu!mania식 strain 모델: 누를 때마다 레인(손가락) strain +2, **손 strain +1**, 전체 strain +1(다른 롱노트를 잡고 있으면 ×1.25), 각각 초당 0.125 · 0.2 · 0.30배로 감쇠한다. 한 순간의 값 = 레인 + 0.6 × 손 + 전체. 손 항 때문에 같은 밀도라도 한 손 트릴·한 손 계단이 양손 교대보다 어렵게 나온다. 400ms 구간 피크를 큰 순서로 0.9배씩 가중합한다. 같은 키 모드(손 배치 포함)에서 레인을 고르게 오가는 일정 속도 스트림으로 보정해 **유효 NPS**로 바꾸고, 키 모드 보정값으로 나눈 뒤 `levelEffectiveNps` 표로 레벨 1–15를 매긴다.

- `handLoad`: 손 strain이 왼손·오른손에 나뉜 비율(엄지 레인은 반반). 곡 선택의 미리보기에 표시한다.
- 스킬 지표(0–1): stream = 4개 이상 이어지는 빠른(≤200ms) 단타 런에 속한 노트 비율, chord = 동치에 얹힌 추가 노트 비율(3동치가 2동치보다 큼), jack = 같은 레인 반복, longNote = 롱노트 개수 비율과 곡 중 롱노트가 눌려 있는 시간의 비율, technical = 8분 그리드 밖 노트 비율과 노트 간격 분포의 엔트로피, stamina = 피크 밀도의 70% 이상인 4초 창의 비율.

## 5. 결정성

- 생성기 입력: AnalysisResult(캐시됨), 키 모드, 공개 파라미터, 시드, 생성기 버전.
- 기본 시드 = `sha256(audioHash | keyMode | difficulty | targetLevel)` 앞 32비트 → 같은 곡의 기본 채보는 항상 같다.
- "다른 패턴"은 새 시드로 다시 만든다. `chartId`가 달라지므로 기록도 따로 남는다.
