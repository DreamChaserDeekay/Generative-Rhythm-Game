## 0. 역할

당신은 리듬게임 엔진, 음악 신호처리(MIR), 게임 UX에 모두 능숙한 시니어 게임 개발자입니다. DJMAX RESPECT V, EZ2ON REBOOT : R, BMS(beatoraja · LR2 · Qwilight), SOUND VOLTEX를 오래 플레이한 사람의 감각으로, 아래 명세에 따라 **사용자가 고른 음악과 난이도로 채보를 자동 생성하고, 그 채보를 SDVX처럼 원근감 있는 3D 트랙 위에서 플레이하는 건반형 리듬게임**을 설계하고 구현하세요.

## 1. 프로젝트 개요

**한 줄 정의**: 내 음악 파일을 넣고 키 모드와 난이도를 고르면, 로컬 분석 서버가 곡을 분석해 그 곡만의 채보를 바로 만들어 주고, 그 채보를 SDVX식 3D 트랙 위에서 DJMAX 판정 기준으로 플레이하는 리듬게임.

**품질 우선순위** (서로 충돌하면 위쪽이 우선)

1. **싱크와 판정의 정확성** — 몇 ms만 어긋나도 나머지가 전부 무의미해진다.
2. **음악과 맞는 채보** — 모든 노트는 실제로 들리는 소리에 대응해야 한다. "지금 이 소리를 치고 있다"는 감각이 핵심이다.
3. **믿을 수 있는 난이도** — 같은 레벨이면 체감 난이도가 비슷하고, 난이도를 올리면 확실히 어려워진다.
4. **손맛** — 즉각적인 판정 피드백, 타격·콤보 연출, 키 반응성.

## 3. 핵심 사용자 흐름

```
곡 추가(로컬 서버로 업로드) → 서버 분석(최초 1회, 캐시) → 곡 선택 → 키 모드·난이도 선택
→ 서버에서 채보 생성 & 미리보기 → 플레이 → 결과 → 리트라이 / 새 시드로 재생성 / 저장
```

1. **곡 추가**: 드래그 앤 드롭 또는 파일 선택으로 로컬 서버에 올린다. 서버가 태그에서 제목·아티스트·앨범아트를 읽고, 없으면 파일명을 쓴다.
2. **분석**: 처음 한 번만 분석하고, 결과는 오디오 해시 기준으로 캐시한다. 진행률 표시를 지원한다.
3. **곡 선택**: 목록(정렬·검색), 자켓, 하이라이트 구간 자동 미리듣기, BPM·길이, 난이도별 기록(클리어 램프·정확도).
4. **난이도 선택**: 프리셋 또는 목표 레벨. 고급 설정(4-5)은 기본으로 접어 둔다.
5. **생성 & 미리보기**: 노트 수, 예상 레벨, 스킬셋 프로필, NPS 그래프, 채보 전체 미니맵. "새 시드로 다시 생성" 버튼.
6. **플레이 → 결과**: 결과 화면에서 리트라이 · 재생성 · 채보 저장/내보내기.

## 4. 채보 자동 생성 (핵심 기능)

### 4-1. 구조

분석·생성·난이도 산정은 모두 **로컬 Python 분석 서버**가 맡고, 브라우저 클라이언트는 받은 채보와 오디오로 플레이만 한다. 서버 내부에서도 분석기와 생성기를 분리하고, 둘 사이의 데이터는 JSON 스키마로 고정한다.

```
[클라이언트] ─업로드─▶ [Python 서버] Analyzer → AnalysisResult → ChartGenerator ⇄ DifficultyEstimator → Chart
[클라이언트] ◀─ Chart JSON + 표준 오디오 ─ [Python 서버]
```

- **분석기는 두 계층**으로 만든다.
  - **기본 분석 (필수)**: numpy · scipy만으로 동작한다. 별도 설치 없이 어느 PC에서나 돌아가야 한다.
  - **ML 백엔드 (선택 설치)**: beat_this, Demucs, basic-pitch, allin1 등. 설치되어 있으면 자동으로 쓰고, 없으면 기본 분석으로 대체한다. 결과는 같은 AnalysisResult 스키마로 낸다.
- **표준 오디오(canonical audio)**: 서버가 업로드 파일을 한 번 디코딩해 FLAC(44.1kHz)로 저장하고, 분석과 클라이언트 재생 모두 이 파일을 쓴다. MP3 인코더 딜레이처럼 디코더마다 수십 ms씩 달라지는 오프셋 문제를 원천 차단하기 위해서다.
- **ChartGenerator ⇄ DifficultyEstimator**: 생성한 채보의 레벨을 산정하고, 목표 범위에 들 때까지 파라미터를 조정해 다시 생성한다.
- **ChartGenerator는 결정적이어야 한다.** 같은 (AnalysisResult, 키 모드, 파라미터, 시드, 생성기 버전)이면 항상 같은 채보가 나온다. 시드 기반 PRNG만 쓴다. 기본 시드는 오디오 해시에서 파생해, 같은 곡의 기본 채보는 항상 같게 한다.
- 성능 목표: 기본 분석은 4분짜리 곡 기준 30초 이내(진행률 표시). 분석 캐시가 있으면 재생성 3초 이내. ML 백엔드는 CPU에서 수 분까지 허용한다.
- **AnalysisResult 필드**: `audioHash`, `durationMs`, `tempoMap`, `beats[{t, isDownbeat}]`, `onsets[{t, strength, band(low|mid|high), source?}]`, `sustains[{t, endT, pitch?, source?}]`, `sections[{t, endT, label?, energy}]`, `analyzer{name, version}`

### 4-2. 오디오 분석 (Analyzer)

| 항목 | 기본 분석 (필수) | ML 백엔드 (선택) | 용도 |
|---|---|---|---|
| 템포·비트·다운비트 | 온셋 강도 곡선 + 템포그램으로 템포 추정, 동적계획법 비트 추적 | beat_this 등 | 비트 그리드, 마디선, 템포 맵 |
| 온셋 | 멀티밴드(저/중/고역) 스펙트럴 플럭스 | 스템별 온셋 | 노트 후보 |
| 소스 분리 | HPSS(타악/화성 분리) + 대역 근사(저역=킥·베이스, 중역=스네어·보컬, 고역=하이햇) | Demucs (drums/bass/vocals/other) | 악기별 레인 매핑, 스템 키음 |
| 음높이 | 화성 성분의 기본 주파수·크로마 기반 간이 윤곽 | basic-pitch | 음높이 → 레인 위치 |
| 지속음 | 온셋 이후 화성 에너지가 유지되는 시간 | 노트 전사 결과의 음 길이 | 롱노트 후보 |
| 곡 구조 | 자기유사 행렬 기반 구간 경계 + RMS 에너지 + 반복 구간 묶기 | allin1 (intro/verse/chorus 등 라벨) | 구간별 밀도, 반복 구간 패턴 재사용, 미리듣기 구간 |

필수 요구사항:

- **고정 BPM 우선**: 대부분의 곡은 BPM이 고정이다. 먼저 "고정 BPM + 오프셋"(필요하면 구간별 고정 BPM) 가설을 전체 온셋과의 정렬도가 최대가 되도록 소수점 셋째 자리 정밀도로 추정한다. 비트 추적기 출력을 그대로 그리드로 쓰면 지터 때문에 채보가 흔들린다. 드리프트가 기준을 넘을 때만 가변 템포 맵으로 전환한다.
- **BPM 배수 오류(절반/두 배) 대응**: 기본은 70–260 BPM 범위로 정규화하고(200 BPM 위는 드럼이 그 템포로 칠 때만), 사용자가 BPM ×2 / ÷2, 탭 템포, 첫 박 오프셋(ms)을 직접 보정할 수 있게 한다. 보정하면 채보를 다시 생성한다.
- 서버는 기본적으로 `127.0.0.1`에만 바인딩하고, 사용자 음원을 PC 밖으로 전송하지 않는다.

### 4-3. 생성 알고리즘 (ChartGenerator)

1. **양자화**: 온셋을 비트 그리드에 스냅한다. 허용 분할은 난이도별로 정한다(4-4 표). 스윙·셔플이 감지되면 셋잇단 그리드를 우선한다. 스냅 오차가 큰 온셋은 낮은 난이도에서 버린다.
2. **후보 점수화**: `점수 = 온셋 강도 × 박자 위치 가중치(강박 > 정박 > 8분 > 16분) × 구간 에너지 × 리듬 소스 가중치`
3. **밀도 제어**: 구간 에너지에 비례하는 목표 NPS 곡선을 만들고, 구간마다 점수가 높은 후보부터 채택한다. 후렴·드롭은 진하게, 인트로·브릿지는 여유 있게. **높은 난이도의 밀도는 없는 소리를 지어내서가 아니라, 더 많은 악기 레이어(하이햇 16비트, 멜로디 잔음 등)를 따라가서 만든다.**
4. **레인 배치**: 규칙과 비용 최소화 탐색(빔 서치 등)을 함께 쓴다.
   - 음악 매핑: 음높이가 높을수록 오른쪽, 같은 소리 반복은 같은/인접 레인(연타·트릴), 상승·하강 프레이즈는 계단, 강한 악센트는 동시치기.
   - 비용 함수: 인체공학 비용(같은 손가락 연속 입력, 한 손 과부하, 무리한 벌림) + 음악 매핑 비용(음높이와 위치의 불일치) + 단조로움 비용(같은 패턴 과반복).
   - 패턴 어휘: 계단, 트릴, 동치(2~N), 연타(잭), 축(앵커), 즈레, 폭타(고밀도 스트림), 롱잡(롱노트를 누른 채 다른 키 타건), 스크래치·사이드 연계.
   - **반복 구간 일관성**: 같은 후렴이 반복되면 같은 패턴(또는 미러 변형)을 다시 쓴다. 사람이 짠 채보처럼 느껴지게 하는 핵심이다.
   - **난이도 간 일관성**: 하위 난이도는 상위 난이도 후보에서 추려 내는 방식을 우선 검토해, 같은 소리는 난이도가 달라도 비슷한 위치·패턴으로 나오게 한다.
5. **특수 노트**
   - 롱노트: 지속음이 난이도별 최소 길이 이상일 때 만든다. 끝점도 그리드에 스냅한다.
   - 스크래치(7K+1S)·사이드(FX): 크래시 심벌, 드롭, 강한 다운비트 같은 임팩트 이벤트에 배치하고, 라이저·스윕은 롱 스크래치나 사이드 롱노트로 만든다.
   - 지뢰 노트: MASTER 전용 선택 옵션.
6. **플레이어빌리티 제약** (생성 중에 강제하고, 별도 린터로 한 번 더 검증)
   - 키 모드별 기본 키 배치와 손가락 모델(레인 → 손·손가락)을 정의하고 이를 기준으로 검사한다.
   - 같은 손가락 연속 입력 최소 간격, 한 손 동시 입력 최대 수, 롱노트를 누르는 동안 같은 손의 추가 입력 제한, 롱노트 끝과 같은 레인 다음 노트 사이 최소 간격.
   - 같은 시각·같은 레인 중복 금지, 롱노트 겹침 금지.
   - 첫 노트 전 최소 리드인(예: 2초)을 확보한다. 부족하면 오디오 재생 전에 대기 시간을 넣는다.
7. **난이도 검증 루프**: DifficultyEstimator가 레벨을 산정하고, 목표 범위를 벗어나면 밀도·분할·동치 파라미터를 조정해 다시 생성한다(최대 N회). 산정 근거(지표)를 결과에 남긴다.

### 4-4. 난이도 프리셋 (4K 기준 예시값, 설정 파일로 분리)

| 난이도 | 레벨 | 평균 NPS | 피크 NPS (1초) | 허용 리듬 (박당 분할) | 최대 동치 | 롱노트 비율 | 같은 레인 최소 간격 | 스크래치·사이드 |
|---|---|---|---|---|---|---|---|---|
| EASY | 1–3 | 1.5–3 | ≤ 5 | 4분 (1) | 1 (강박만 2) | 5–10% | ≥ 450ms | 거의 없음 |
| NORMAL | 4–6 | 3–5 | ≤ 8 | 8분 (2) | 2 | 10–15% | ≥ 300ms | 가끔 |
| HARD | 7–9 | 5–8 | ≤ 12 | 8분 셋잇단 (3), 16분 일부 (4) | 3 | 10–20% | ≥ 200ms | 보통 |
| EXPERT | 10–12 | 8–12 | ≤ 18 | 16분 (4), 16분 셋잇단 (6) | 3–4 | 제한 완화 | ≥ 140ms | 잦음 |
| MASTER | 13–15 | 12 이상 | 제한 완화 | 32분 버스트 (8)까지 | 키 수 이내 | 제한 완화 | ≥ 100ms | 잦음 |

- 키 모드 보정: 키가 많을수록 같은 레벨에서 허용 NPS를 높인다(예: 7K ≈ 4K × 1.3).
- 목표 레벨을 직접 고르면 프리셋 사이를 보간한다.

### 4-5. 고급 생성 옵션

- 밀도 50–150%, 롱노트 비율, 최대 동치 수, 스크래치·사이드 빈도, 시드
- 패턴 스타일: 밸런스 / 스트림·계단 / 동치·폭타 / 연타 / 롱노트 / 테크니컬(엇박·셋잇단·즈레) / 멜로디 추종(BMS 키음 배치처럼 음높이를 레인 위치로)
- 리듬 소스: 자동(구간별 주도 악기) / 드럼 / 베이스 / 멜로디 / 보컬

### 4-6. 난이도 산정 (DifficultyEstimator)

- 지표: 총 노트 수, 평균·피크 NPS(1초·4초 윈도), 동치 비율, 롱노트 비율·롱잡 빈도, 최소 연타 간격, 손 교대 패턴, 구간별 체력 부담(스태미나)
- 방식: osu!mania의 strain 방식(레인별·전체 strain을 감쇠 누적해 구간 피크의 가중합을 구함)이나 Etterna MSD 방식을 참고해 구현하고, 결과를 레벨 1–15로 매핑한다. 매핑 임계값은 설정 파일로 분리한다.
- 모든 채보에 레벨과 함께 스킬셋 프로필(스트림 / 동치 / 연타 / 롱노트 / 테크니컬 / 스태미나)을 표시한다.

### 4-7. 채보 포맷 (예시)

```json
{
  "formatVersion": 1,
  "meta": {
    "chartId": "sha256:…",
    "audioHash": "sha256:…",
    "title": "Song Title",
    "artist": "Artist",
    "keyMode": "7K+1S",
    "lanes": ["SC", "1", "2", "3", "4", "5", "6", "7"],
    "difficulty": "HARD",
    "level": 9,
    "skillset": { "stream": 0.62, "chord": 0.41, "jack": 0.18, "longNote": 0.33, "technical": 0.27, "stamina": 0.55 },
    "generator": {
      "version": "0.1.0",
      "analyzer": "core-1.0",
      "seed": 20261017,
      "params": { "density": 1.0, "longNoteRatio": 0.15, "maxChord": 3, "style": "balanced", "rhythmSource": "auto" }
    }
  },
  "timing": {
    "offsetMs": 132.5,
    "tempoMap": [{ "beat": 0, "bpm": 128.0 }],
    "meter": [{ "measure": 0, "beatsPerMeasure": 4 }]
  },
  "sections": [{ "startBeat": 0, "label": "intro", "energy": 0.3 }],
  "notes": [
    { "beat": 4.0, "t": 2007.5, "lane": 3, "type": "tap" },
    { "beat": 4.5, "t": 2241.9, "lane": 6, "type": "hold", "endBeat": 6.0, "endT": 2945.0 },
    { "beat": 6.0, "t": 2945.0, "lane": 0, "type": "tap" }
  ]

```

- 노트마다 `beat`(그리드·편집·내보내기용)와 `t`(표준 오디오 기준 ms, 플레이용)를 둘 다 저장한다.
- `chartId = hash(audioHash + keyMode + params + seed + generatorVersion)`. 기록은 chartId에 묶는다. 생성기 버전이 바뀌면 이전 기록은 구버전 채보 기록으로 구분한다.
- 분석 결과와 생성한 채보는 서버 데이터 폴더에 캐시해, 다음부터는 바로 플레이할 수 있게 한다.
- 포맷 명세는 `docs/CHART_FORMAT.md`로 문서화한다.

## 5. 게임플레이

### 5-1. 키 모드와 기본 키 배치 (전부 리바인딩 가능)

| 모드 | 기본 키 |
|---|---|
| 4K | D F J K |
| 5K | D F Space J K |
| 6K | S D F K L ; |
| 7K+1S | 스크래치 Left Shift + S D F Space J K L (BMS식 Z S X D C F V 프리셋도 제공) |
| 8K | A S D F J K L ; |
| 사이드(FX) 레인 | Left Shift / Right Shift — 4K·6K에 좌우 사이드 레인 추가 (DJMAX 사이드 트랙 방식) |

- 입력은 물리 키 코드(웹: `KeyboardEvent.code`) 기준으로 처리해 한글 IME 상태에서도 동작하게 하고, 키 반복(`repeat`) 이벤트는 무시한다.
- 키보드 동시 입력(고스팅) 테스트 화면을 제공한다.
- 스크래치 레인 위치(좌/우)를 고를 수 있다.

### 5-2. 노트 종류

- 일반 노트, 롱노트, 스크래치 노트·롱 스크래치, 사이드 노트·사이드 롱노트, 지뢰(선택)
- 롱노트 판정은 DJMAX 방식을 기본으로 한다(5-4).

### 5-3. 타이밍과 싱크 (가장 중요)

- **곡 위치의 기준은 오디오 클럭 하나뿐이다.** (웹: `AudioContext` 시간과 `performance.now()`를 `getOutputTimestamp()`로 매핑하고 `outputLatency`를 반영) 프레임 delta를 누적해 곡 위치를 계산하지 않는다.
- **판정은 렌더링 프레임과 무관하게**, 입력 이벤트의 타임스탬프(웹: `event.timeStamp`)를 곡 시간으로 변환해서 계산한다.
- 클라이언트는 서버의 표준 오디오(FLAC)를 Web Audio로 디코딩해 재생한다. 채보의 `t`는 이 오디오의 첫 샘플을 0ms로 한다.
- 오프셋은 두 가지로 분리한다: 판정 오프셋(입력 타이밍 보정)과 표시 오프셋(노트를 그리는 위치 보정).
- 오프셋 캘리브레이션 화면: 메트로놈에 맞춰 탭하면 평균 오차로 자동 설정한다. 결과 화면에서도 평균 오차로 오프셋을 추천한다.
- 화면 밖 노트 컬링과 오브젝트 풀링으로 3,000노트 이상에서도 모니터 주사율(60–240Hz)을 유지한다.
- 개발용 디버그 오버레이: FPS, 오디오 시간, 렌더 지연, 입력 오차 통계.

### 5-4. 판정 — DJMAX RESPECT V 기준

판정 엔진은 하나로 만든다(입력과 노트의 ms 오차 → 판정). 판정 범위는 DJMAX RESPECT V(PC판: BPM과 무관하게 ms 고정)를 따른다.

| 판정 | NORMAL | HARD JUDGEMENT (×1/2) | MAX JUDGEMENT (×1/4) | 근거 |
|---|---|---|---|---|
| MAX 100% | ±41.67ms | ±20.83ms | ±10.42ms | 60fps 2.5프레임, 커뮤니티 정설 |
| MAX 90% | ±60ms | ±30ms | ±15ms | 커뮤니티 실측 추정 |
| MAX 80% | ±78ms | ±39ms | ±19.5ms | 커뮤니티 실측 추정 |
| MAX 70% ~ MAX 10% | ±78 ~ ±160ms 구간을 7등분 | ×1/2 | ×1/4 | 실측값 없음 — 보간 |
| MAX 1% | ±180ms | ±90ms | ±45ms | 커뮤니티 실측 추정(177~180ms) |
| BREAK | 미처리, MAX 1%보다 더 빗나간 처리, 롱노트 조기 릴리즈 | | | |

- 수치는 `config/judgement.json`에 두고, 값마다 출처와 추정 여부를 남긴다. 더 정확한 측정값이 나오면 설정만 바꿔 반영할 수 있게 한다.
- **콤보와 게이지**: MAX 1%까지는 콤보가 유지되고 게이지도 줄지 않는다. 콤보는 BREAK에서만 끊긴다.
- **이른 입력**: MAX 1% 범위보다 조금 더 이른 입력(간접 미스 구간, 기본 1% 바깥 40ms)은 노트를 소모하며 BREAK가 된다. 그보다 이른 입력은 무시한다.
- **롱노트 (DJMAX식)**: 시작은 타이밍 판정, 누르고 있는 동안 일정 간격(기본 1/4박)마다 콤보 틱, 끝까지 유지하면 끝 판정 MAX 100%, 끝나기 전에 떼면 BREAK. 끝 직전 유예 시간은 설정값으로 둔다.
- **정확도(Rate)** = 판정 %의 평균(소수 둘째 자리). 판정 대상은 일반 노트, 롱노트 시작, 롱노트 끝이다.
- 판정 표기·점수 공식·게이지 규칙은 **룰셋**으로 분리해 갈아끼울 수 있게 하되, 판정 범위는 위 DJMAX 기준을 공유한다. 등급형(EZ2ON 참고)·EX-SCORE형(BMS 참고) 표기는 같은 판정 구간을 묶어 보여 주는 프리셋으로 만든다.

### 5-5. 점수 · 콤보 · 게이지 · 클리어 램프

- 점수: 1,000,000점 만점 = `Σ판정% ÷ (판정 대상 수 × 100) × 1,000,000`
- 콤보: 판정 대상과 롱노트 틱마다 1씩 오르고, BREAK에서만 끊긴다.
- FEVER(선택): 높은 판정으로 게이지를 채워 발동하는 연출·보너스.
- 게이지: NORMAL(약 20%에서 시작, 끝날 때 80% 이상이면 클리어)을 기본으로, ASSIST EASY / EASY / HARD(0%가 되면 즉시 실패) / EX-HARD / 서든 데스 / 노페일(연습용)을 추가한다. MAX 1%는 게이지를 깎지 않는다. 회복·감소량은 노트 수 기반으로 자동 산정한다(BMS #TOTAL 개념).
- 클리어 램프: FAILED · CLEAR · MAX COMBO(풀콤보) · PERFECT PLAY(전 판정 MAX 100%), 게이지 종류별 램프(ASSIST · EASY · HARD · EX-HARD). 채보별 최고 기록을 저장한다.

### 5-6. 화면과 옵션

- **SDVX식 3D 트랙 (기본 시점)**
  - 트랙(기어)은 3D 평면이다. 카메라는 판정선 뒤쪽 낮은 위치에서 트랙을 따라 비스듬히 바라본다. 판정선은 화면 아래쪽에, 트랙 끝은 화면 위쪽 소실점 근처에 놓인다.
  - 노트는 트랙 끝에서 작게 나타나 다가올수록 커진다. 레인 구분선, 마디선, 트랙 끝 페이드로 원근 속에서도 읽기 쉽게 만든다.
  - 카메라 프리셋(약한 원근 / SDVX(기본) / 강한 원근)과 세부 값(카메라 높이·거리·시야각·트랙 길이)을 조절할 수 있다.
  - 판정·콤보 텍스트는 트랙 위 3D 위치를 화면 좌표로 투영해 HUD에 그린다.
  - (선택) SDVX식 카메라 연출: 드롭·구간 전환에서 트랙 기울기·줌 펄스. 강도 조절과 끄기를 지원한다.
- **배속**: 0.5–10.0배(0.1 단위) + **가시 시간 고정 모드**(노트가 트랙 끝에서 판정선까지 오는 시간을 ms로 고정하는 BMS 그린 넘버 방식). 속도는 트랙 위 거리(월드 좌표) 기준으로 정의한다. 플레이 중 단축키로 바로 바꿀 수 있다.
- **레인 커버**: SUDDEN+ / HIDDEN+ / LIFT. 트랙 위 거리 구간을 가리는 방식으로 구현하고, 플레이 중 조절 가능하게 한다.
- **스크롤**: 기본은 시간 기반 등속 스크롤(가변 템포에서도 속도 일정), 옵션으로 BPM 연동 스크롤.
- **배치 옵션**: MIRROR / RANDOM / R-RANDOM / S-RANDOM / H-RANDOM. 생성된 채보 위에 적용하고, 기록에 사용한 옵션을 표기한다.
- **플레이 HUD**: 판정, 콤보, FAST/SLOW와 ms 오차(옵션), 진행 바, 정확도, 최고 기록 대비 페이스메이커.
- **연출**: 판정선 글로우, 키 빔, 타격 이펙트, 롱노트 홀드 이펙트, 콤보 마일스톤, MAX COMBO · PERFECT PLAY 연출.
- **배경**: 앨범아트 블러 + 오디오 반응형 비주얼라이저. 사용자 영상(BGA) 지정, 배경 밝기 조절.
- **오토 플레이**: 생성된 채보를 자동으로 연주하는 데모 모드(채보 확인·싱크 검증용).
- **연습 모드**: A–B 구간 반복, 시작 위치 지정, 재생 속도 0.5–1.5배(피치 유지), 노페일. 연습 기록은 공식 기록에 넣지 않는다.
- 일시정지·재개(재개할 때 카운트다운), 퀵 리트라이 단축키.
- **타격음**: 선택(기본 OFF). ML 백엔드로 스템을 분리했다면 **스템 키음 모드**를 지원한다. 리드 악기 스템은 노트를 쳤을 때만 제 볼륨으로 나오고, 놓치면 잠깐 작아진다. BMS · DJMAX의 키음 손맛을 흉내 내는 기능이다.

### 5-7. 결과 화면

- 판정별 개수, 최대 콤보, 점수, 정확도, 클리어 램프, 신기록 여부와 차이
- FAST/SLOW 개수, 타이밍 오차 히스토그램, 평균 오차·표준편차, 오프셋 추천
- 게이지 그래프와 밀도 그래프 위에 BREAK 위치 표시
- 리트라이 / 새 시드로 재생성 / 채보 저장·내보내기 / 리플레이 저장

## 6. 곡 선택 · 라이브러리 · 설정

- 모든 메뉴를 키보드(와 게임패드)만으로 조작할 수 있다.
- 곡 목록 정렬·검색·필터(제목, 아티스트, BPM, 길이, 최근 플레이, 클리어 램프).
- 곡 정보 수정: 제목·아티스트·BPM·첫 박 오프셋 → 재분석·재생성.
- 설정: 모드별 키 바인딩, 판정 모드(NORMAL / HARD / MAX JUDGEMENT), 오프셋 2종과 캘리브레이션, 볼륨(음악·효과음), 기본 배속, 카메라 프리셋, 레인 폭, 노트 스킨과 레인 색 배치(색각 이상 대응 팔레트 포함), 판정 표시 위치, 강한 플래시 연출 끄기, 언어.
- 디자인: 오리지널 다크 테마 + 네온 포인트 컬러, 16:9 기준 반응형.
- 저장: 라이브러리(표준 오디오·분석 결과·채보·기록)는 로컬 서버의 데이터 폴더(SQLite + 파일)에, 클라이언트 설정은 브라우저 localStorage에 둔다.

## 7. 기술 스택 (권장 — 더 나은 선택이 있으면 근거와 함께 제안)

- **클라이언트**: TypeScript(strict) + Vite, 게임 화면은 Three.js(WebGL, 원근 카메라), 메뉴는 React, HUD는 DOM 오버레이, 오디오는 Web Audio API
- **분석 서버 (필수)**: Python 3.11+ · FastAPI · uvicorn · numpy · scipy · PyAV(디코딩) · soundfile(FLAC) · mutagen(태그·커버) · SQLite
- **ML 백엔드 (선택)**: beat_this · Demucs · basic-pitch · allin1. 각 라이브러리는 설치 호환성과 라이선스를 확인한 뒤 채택한다.
- 테스트: Vitest(클라이언트 유닛), Playwright(E2E), pytest(서버)
- 데스크톱 패키징(후순위): Tauri 또는 Electron + 분석 서버 동봉 — 오디오 지연과 일관성을 비교해서 결정
- **라이선스 주의**: essentia(AGPL-3.0), madmom 사전학습 모델(CC BY-NC-SA, 비상업), aubio(GPL-3.0) 등은 배포·상용화에 제약이 있다. 쓰게 되면 README에 명시하고 어댑터로 감싸 교체할 수 있게 한다.

## 8. 개발 단계와 완료 조건

**Phase 0 — 설계와 기술 검증**

- 아키텍처 문서, 폴더 구조, 오디오 싱크·판정 프로토타입(클릭 트랙에 맞춰 SDVX식 3D 트랙에서 노트가 내려오고 DJMAX 기준으로 판정되는 최소 데모)
- 완료 조건: 가상 입력을 실제 입력 경로로 주입하는 오토 플레이가 전 노트 MAX 100%를 받는다. 사람이 메트로놈에 맞춰 치면 평균 오차·표준편차가 표시되고, 오프셋을 적용하면 평균 오차가 0 근처로 수렴한다.

**Phase 1 — MVP: 처음부터 끝까지 한 판**

- 곡 업로드 → 서버 기본 분석 → 4K · 7K+1S 채보 생성(5개 난이도) → SDVX식 트랙에서 플레이(일반·롱노트·스크래치) → DJMAX 판정·콤보·정확도·점수·NORMAL 게이지 → 결과 화면
- 키 바인딩, 판정 모드, 배속, 오프셋, 카메라 프리셋 설정, 일시정지·리트라이, 오토 플레이, 기록 저장
- 분석 결과 시각화(파형 + 온셋 + 비트 그리드 + 구간) 개발 도구
- 완료 조건:
  - 합성 테스트 음원(고정 BPM)에서 곡 전체에 걸친 그리드 누적 오차 ≤ 10ms
  - 같은 입력·시드 → 같은 채보(해시 일치)
  - 모든 난이도의 채보가 플레이어빌리티 린터 통과
  - 난이도가 오를수록 노트 수·평균 NPS·추정 레벨이 단조 증가
  - 4분짜리 곡 기본 분석 30초 이내, 분석 캐시가 있으면 재생성 3초 이내

**Phase 2 — 리듬게임다운 깊이**

- 5K · 6K · 8K, 사이드(FX) 레인, 룰셋 표기 프리셋, FEVER, 게이지 종류·클리어 램프, 배치 옵션, 레인 커버·가시 시간 고정, 연습 모드, 결과 분석(히스토그램·오프셋 추천 고도화), 난이도 산정 고도화, 고급 생성 옵션, 채보 미리보기 미니맵

**Phase 3 — 생성 품질 고도화**

- ML 백엔드(스템 분리·음높이·곡 구조), 악기별 레인 매핑, 반복 구간 패턴 일관성 강화, 스템 키음 모드, SDVX식 카메라 연출, 비주얼라이저·BGA, 스킨 시스템

**Phase 4 — 확장**

- 채보 에디터(생성 결과 수정 + 해당 위치부터 테스트 플레이)
- 가져오기/내보내기: BMS · bmson · osu!mania. BMS 가져오기는 키음(#WAV)·BGM 채널 재생, BPM 변속·STOP 지원이 필요하다. 내보낼 때 음원은 포함하지 않고 파일 참조만 한다.
- 리플레이, 게임패드·전용 컨트롤러(폴링 주기가 판정 정밀도를 좌우하므로 별도 처리), 데스크톱 패키징
- (연구) 기존 채보 데이터로 학습한 ML 생성 모델 — 학습 데이터 라이선스 확인 필수

## 9. 테스트와 품질 기준

- **판정 엔진**: DJMAX 판정 구간 경계값(NORMAL/HARD/MAX), 간접 미스 구간, 롱노트(틱·조기 릴리즈·끝 판정), 동시 입력, 콤보·게이지 규칙
- **생성기**: 결정성, 린터(중복·겹침·연타 간격·동치 수·손 부담), 난이도 단조성, 리드인 확보
- **분석기**: 코드로 합성한 테스트 음원(예: 120/128/174 BPM 드럼 루프, 셋잇단·스윙 패턴, 중간에 템포가 바뀌는 곡)의 정답과 비교. **저작권 있는 음원은 저장소에 넣지 않는다.**
- **서버 API**: 업로드 → 분석 → 채보 생성 → 기록 저장 흐름
- **렌더러**: 판정선·레인 경계가 기대한 화면 좌표로 투영되는지 수치 테스트
- **생성 품질(선택)**: 공개 라이선스로 배포된 사람 제작 채보가 있으면 노트 타이밍 F1을 비교한다(mir_eval 방식).
- **E2E**: 곡 추가 → 생성 → 오토 플레이 → 결과 화면 흐름을 자동 테스트
- **성능**: 3,000노트 채보에서 프레임 타임 로그로 프레임 드롭이 없는지 확인

2. Phase가 끝날 때마다 실행 가능한 상태와 테스트 통과를 유지하고, 의미 있는 단위로 커밋하세요.
3. 핵심 로직은 UI와 분리된 순수 모듈로 작성해 테스트할 수 있게 하세요. 판정·점수는 DOM에 의존하지 않는 TypeScript 모듈로, 분석·생성·난이도 산정은 서버 없이도 호출되는 Python 모듈과 CLI로 만드세요.
4. 판정 범위, 난이도 프리셋, 레벨 매핑 같은 수치는 하드코딩하지 말고 `config/`로 분리하세요.
5. 문서: README(설치·실행·조작법), `docs/ARCHITECTURE.md`, `docs/CHART_FORMAT.md`, 생성 알고리즘 설명.
6. Phase를 마칠 때마다 구현 내용, 실행 방법, 테스트 결과, 알려진 한계, 다음 단계를 보고하세요.
7. 이 문서에 없는 결정은 1장의 품질 우선순위를 기준으로 내리고, 판단 근거를 보고에 남기세요.

### 하지 말 것

- 프레임 delta를 누적해 곡 위치나 판정 시간을 계산하는 것
- 분석용 디코딩과 재생용 디코딩을 서로 다른 디코더로 따로 하는 것(표준 오디오를 쓸 것)
- 소리가 없는 곳에 밀도를 채우려고 노트를 넣는 것, 순수 랜덤으로 레인을 배치하는 것
- 비트 추적기 출력을 보정 없이 그대로 그리드로 쓰는 것
- 튜닝 수치를 코드에 하드코딩하는 것
- 저작권 음원이나 다른 게임의 에셋을 저장소에 넣는 것
- 사용자 음원을 PC 밖(로컬 분석 서버 이외)으로 전송하는 것
