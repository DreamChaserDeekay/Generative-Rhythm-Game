# 실제 플레이어용 찾기 테스트 자료

대리 테스트(서브에이전트)는 사람의 결과가 아닙니다. 아래 자료로 플레이어 5명에게 직접 돌려 주세요. 한 사람에 30~40분입니다.

## 누구에게

| 참가자 | 조건 |
|---|---|
| P1 | 리듬게임을 거의 안 해 본 사람 (처음 온 사람) |
| P2 | 리듬게임을 가끔 하는 사람 |
| P3 | 건반형 리듬게임을 매일 하는 사람 |
| P4 | 고수 (옵션과 오프셋을 스스로 맞추는 사람) |
| P5 | 패드나 전용 컨트롤러로 하는 사람 |

이 게임을 이미 써 본 사람은 메뉴를 외우고 있어 맞지 않습니다. 써 본 적 없는 사람으로 구하세요.

## 1. 트리 테스트 (15분)

메뉴 이름만 한 단계씩 보여 주고 "이 일을 하려면 어디로 가겠는가"를 고르게 합니다. 화면도 도움말도 없습니다.

### 준비

- Node.js가 있는 컴퓨터에서 저장소의 `client` 폴더를 엽니다.
- 참가자마다 구조 하나만 줍니다(같은 사람이 두 구조를 하면 두 번째는 배운 뒤라 비교가 안 됩니다). 5명이면 현재 2명, 제안 3명처럼 나누고, 승인한 제안 구조에 맞춰 `p1`이나 `p2`를 고르세요.
- 시작: `node audit/treetest.mjs start <current|p1|p2> human-<구조>-<번호>` (예: `human-current-1`)

### 진행

1. 이렇게 말해 줍니다: "게임을 평가하는 것이지 당신을 시험하는 것이 아닙니다. 이름만 보고 떠오르는 대로 고르고, 생각을 소리 내어 말해 주세요."
2. 참가자가 번호를 말하면 진행자가 `node audit/treetest.mjs pick human-<…> <번호>`를 대신 칩니다(참가자가 직접 쳐도 됩니다). 잘못 들어왔다 싶으면 0으로 돌아갑니다.
3. 진행자는 도와주지 않습니다. 이름의 뜻을 물으면 "어떤 뜻일 것 같으세요?"라고 되묻고 그 말을 적습니다.
4. 과제 20개가 끝나면 `node audit/treetest.mjs score`로 채점합니다. 결과는 `docs/audit/08-findability.md`에 대리 참가자와 함께 집계되니, 사람만 보려면 `sessions/`에서 `human-`으로 시작하는 파일만 남기고 돌리세요.

### 과제 (스크립트가 사람마다 순서를 섞어 냅니다)

| # | 과제 | 빈도(추정) |
|---|---|---|
| Q01 | 박자에 맞춰 치는데도 계속 "늦게 쳤다(SLOW)"고 나온다. 내 손이 아니라 기기(모니터·헤드폰) 탓 같다. 어디서 고치겠는가? | 하루 한 번 |

| Q20 | 내 키보드가 키 여러 개를 한꺼번에 눌렀을 때 일부를 놓치는지 확인하고 싶다. | 처음 한 번 |

## 2. 카드 분류 (15분)

설정 항목을 플레이어가 **자기 생각대로** 어떻게 묶는지 봅니다. 탭을 어떻게 나눌지의 근거가 됩니다.

### 준비

- `cards.txt`의 82장을 한 장에 하나씩 인쇄하거나 포스트잇에 적습니다(두 곳에 있는 항목은 한 장만).
- 빈 카드 10장과 펜.

### 진행 (열린 분류)

1. "이 카드들은 리듬게임의 설정 항목입니다. 비슷하다고 생각하는 것끼리 묶어 주세요. 묶음은 몇 개여도 좋습니다."
2. 뜻을 모르는 카드는 "모르겠음" 더미에 따로 둡니다. 이 더미가 이름의 문제를 알려 줍니다.
3. 다 묶으면 묶음마다 이름을 빈 카드에 적게 합니다.
4. 마지막으로 묻습니다: "이 가운데 판마다 또는 곡마다 바꿀 것 같은 카드를 골라 주세요." (플레이 옵션에 둘 것의 근거)

### 기록 양식

| 참가자 | 묶음 이름 | 그 묶음의 카드 | "모르겠음"에 둔 카드 | 판마다·곡마다 바꾼다고 고른 카드 |
|---|---|---|---|---|
| | | | | |

### 읽는 법

- 5명 가운데 4명 이상이 같은 묶음에 둔 카드 쌍은 같은 탭에 두는 것이 맞습니다. 지금 다른 탭에 있으면 옮길 후보입니다.
- 3명 이상이 "모르겠음"에 둔 카드는 이름을 바꿀 후보입니다.
- 참가자가 붙인 묶음 이름이 탭 이름의 후보입니다.
- 5명은 경향을 보는 수입니다. 비율을 일반화하지 마세요.
