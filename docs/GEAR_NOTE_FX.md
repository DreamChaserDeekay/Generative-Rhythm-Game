## 타격 효과는 그림으로 그린 프레임 애니메이션 (2026-11-11)

사용자 의견(2026-11-11): 스킨 2 · Grok · Claude · GPT · 6 · 7 · 9 · 10 · 11의 이펙트가 "단순 도형 (원, 선)으로 이루어진 티가 너무 나고, 애니메이션도 너무 밋밋", "지속시간은 … 0.4초 이하가 이상적", "GEMINI API 우선으로 이미지 생성 방식으로 다시 작성", 후보에 없는 스킨도 코드 그림이면 이미지로. 그래서 그때의 **15개 스킨 모두** 타격 효과를 그림으로 바꿨습니다(스킨 7 · 9, 곧 무지개와 크림슨은 2026-11-13에 없애 지금은 13개입니다: 아래 "기어 하단은 입체 그림" 절). 아래 스킨별 절의 "타격 효과" 설명 가운데 코드 그림(도형)의 묘사는 그림이 없을 때 나오는 대역(`tintArt.ts`의 `SKIN_HITS`)의 것입니다.

- 효과마다 Gemini가 **16프레임(4×4)의 프레임별 애니메이션 시트**를 그립니다: 치는 순간 한 장, 롱노트를 누르는 동안(반복) 한 장. 프레임마다 다른 그림이라 불꽃이 갈라지고 파편이 돌며 흩어집니다.
- 치는 순간은 **0.32초**에 끝납니다(프레임 9~12장을 28~37fps로). 거의 빈 첫 프레임은 빼서 키를 누르는 순간 섬광이 바로 보입니다. 누르는 동안은 24fps 반복입니다.
- 스킨의 효과는 제 색 그대로 화면에 더하고(매니페스트 `plain`), 기본 스킨의 플래시만 흰빛에 레인 색을 입힙니다.
- 이름이 바뀐 것: 파이어스타터 "불똥" → "불꽃놀이"(처음에는 "불꽃": 아래), GPT "입력 중 점" → "물방울 왕관", Grok "펜 엑스" → "엑스 섬광"(굵은 획과 가는 획이 엇갈린 X가 번쩍이고 깨져 흩어짐), Claude "손 빛살" → "붓 빛살", 화이트 라인 "선 고리" → "선 불꽃".

| 스킨 | 치는 순간 | 누르는 동안 |
|---|---|---|
| 기본 "플래시" | 별 모양 섬광 → 전기가 튀는 충격파 고리 → 가는 호와 반짝임 | 흰 심지 둘레에 전기 줄기 |
| 크리스털 "크리스털 분광" | 마름모 섬광 → 무지개 변이 난 수정 조각이 사방으로 깨져 날아감 | 마름모 빛과 분광 반짝임 |
| 하늘 "구름 깃털" | 햇살 → 구름 고리가 부풀며 흰 깃털이 날림 | 햇빛 공과 감도는 구름 |
| 파이어스타터 "불꽃놀이" | 흰 금빛 점이 터져 진홍·분홍 빛줄기(머리는 흰 금빛 구슬)가 둥글게 퍼지고, 줄기가 사라진 자리에서 금빛 반짝이가 깜빡이다 사라짐 | 스파클러: 흰 금빛 심에서 끝이 갈라지는 가는 불티가 사방으로 튐 |
| GPT "물방울 왕관" | 청록 빛이 왕관 모양으로 튀어 오르고 물결 고리가 퍼짐 | 청록 구슬과 번지는 물결 |
| Gemini "반짝임" | 네 갈래 큰 별 → 파랑 · 보라 · 분홍의 작은 별들이 흩어져 깜빡임 | 깜빡이는 네 갈래 별 |
| Grok "엑스 섬광" | 두 획이 엇갈려 X가 되고 번쩍인 뒤 모난 조각으로 깨져 날아감(흑백) | 깜빡이는 작은 X |
| Claude "붓 빛살" | 테라코타 붓 자국이 해처럼 퍼지고 물감 점이 튐 | 들쭉날쭉 숨 쉬는 붓 빛살 |
| 아쿠아 "록온" | 육각 고리가 열리며 청록 플라스마와 분홍 파편 | 돌아가는 육각 고리와 심지 |
| 스틸 "십자 섬광" | 십자 플레어와 쇠 불똥, 가는 충격파 고리 | 용접 불빛과 튀는 불똥 |
| 레드라인 "글리치" | 흰 막대가 어긋난 조각으로 찢기고 빨강 · 흰 픽셀이 튐 | 좌우로 떨리는 빨간 조각 |
| 화이트 라인 "선 불꽃" | 가는 흰 선으로 그린 불꽃놀이가 피었다 떨어짐 | 다시 그려지는 선 별 |
| 별밤 "별빛" | 금빛 별 → 별가루와 작은 별들이 흩어져 깜빡임 | 깜빡이는 금빛 별과 별가루 |

사용자 의견(2026-11-11, 위 효과들을 본 뒤): "Firestarter는 불꽃놀이 느낌이 나야하는데 용암같다". 처음 그림은 녹은 주황색 불덩이와 휘감기는 불길, 불씨였습니다(프롬프트가 "molten orange"의 불이었음). 그래서 파이어스타터의 효과를 **불꽃놀이**로 다시 그렸습니다: 불길·불덩이·연기 없이 가는 빛줄기와 빛점만으로, 치는 순간은 국화 모양으로 터지는 불꽃놀이(진홍·분홍 줄기, 흰 금빛 머리, 금빛 반짝이), 누르는 동안은 스파클러입니다. 이름도 "불꽃"에서 "불꽃놀이"로 바꿨습니다.

코드: `scripts/assets/make_skin_fx.py`(프롬프트와 생성), `scripts/assets/build_skin_fx.py`(검정 정리 · 가장자리 흐림 · 프레임 고르기 · 0.32초 맞춤 → `client/public/media/fx/`), `styleArt.ts`의 `HIT_ART`(스킨의 효과 이름 → 매니페스트 id, 기본 스킨은 `basic`), `skinArt.ts`의 `MediaTexture.plain` · `cored`, `TrackRenderer.ts`의 `tinge`(제 색 플립북은 흰색으로 그대로 더함). 출처와 프롬프트: `assets-src/PROVENANCE.md`.

## 기어 하단은 그림 한 장: 표시창 · 날개 · 문장 (2026-11-11)

> 2026-11-13: 이 절의 평면 그림(표시창 · 날개 · 문장)은 다음 절의 입체 그림으로 모두 바뀌었고, SCORE와 SPEED는 기어 옆으로 나갔습니다. 판정선 높이와 키 줄에 대한 설명은 지금도 맞고, 나머지는 그때의 기록입니다(그때는 스킨이 15개였습니다). 이 그림들을 만들던 `scripts/assets/make_skin_panels.py`는 지웠습니다.

사용자 요청(2026-11-11): "판정선을 더 위로 올리고 기어 하단 영역 자체를 넓히라", 이어서 "확장된 기어 하단에 맞게 스킨마다 하단 영역 이미지를 새로 생성해서 적용해줘 … 하단 영역이 여유가 있어지니까 컨셉에 맞는 디자인, 꾸밈 요소를 더 넣을 수 있겠지?". 그래서 15개 스킨 모두 **키 줄 아래의 받침이 Gemini가 그린 그림 한 장**입니다. 아래 스킨별 절의 "받침" · "수치" 설명 가운데 키 줄 아래의 묘사는 그림을 못 읽었을 때 나오는 코드 그림의 것입니다.

- **판정선**: 화면 높이의 72%(77%에서 올림). 기어 하단이 화면의 28%를 차지합니다(`config/camera.json`의 `judgeLineY`, 프리셋 네 개를 함께 맞춤).
- **구성**(그림 21:9, 위에서 내려다본 평면): 위쪽 가운데에 넓고 어두운 **표시창**(폭의 절반 남짓), 양옆 **날개**에 컨셉 장식(기본: 스피커 그릴 · 노브 · 하늘색 빛줄 / 크리스털: 수정 날개와 사파이어 / 하늘: 뭉게구름과 깃털 / 파이어스타터: 검은 칼날 무늬와 크롬 스피커 / GPT: 대화 말풍선 줄 / Gemini: 오로라와 네 갈래 별 / Grok: 궤도와 별자리 / Claude: 손그림 낙서 / 아쿠아: 흰 장갑판과 청록 통풍구 / 스틸: 깎은 패널과 파란 슬롯 / 무지개: 사탕 캡슐과 스프링클 / 레드라인: 빨간 사선 띠와 망점 / 크림슨: 진홍 빛줄의 장갑 / 화이트 라인: 선 도면 / 별밤: 별자리와 달의 위상), 표시창 바로 아래에 큰 **문장**(조그 휠, 수정 메달, 날개 문장, 불꽃 방패, 꽃 매듭, 별 원반, 블랙홀, 해 도장, 리액터, 기계 원반, 무지개 돔, 과녁, 칼날 문장, 얼굴 고리, 날개 별).
- **수치**: SCORE(위, 크게)와 SPEED(아래, 가운데)를 표시창 유리 위에 두 줄로 씁니다. 표시창은 모든 스킨이 어두운 유리라 글자는 밝은색입니다(GPT · Claude · 무지개도 표시창 위에서는 흰 글자). RATE는 판정 글자 아래로 갔습니다(아래 절).
- **카메라별로 보이는 범위**: 기본(SDVX)은 그림의 위쪽 45%쯤, 즉 표시창과 날개, 문장의 윗부분이 화면 아래에 걸쳐 보입니다. 약한 원근 · 평면은 문장 전체와 몸통까지 보입니다. 강한 원근(LOW)은 표시창까지만 보이고 두 줄을 보이는 만큼에 맞춰 씁니다.
- **키 줄**은 레인을 따라야 하므로 그대로 코드로 그립니다(누르면 켜지는 키캡 포함). 기어의 조명 가운데 키 줄의 빛은 그대로이고, 문장 자리 조명(`emblem`)은 그림의 문장에 맞춰 켜집니다.

같이 바뀐 것:

- **수치는 기어 옆에**: 하단에 표시창이 없으므로 SCORE · MAX COMBO · SPEED는 기어 왼쪽에 바탕 없이 씁니다(`deckReadouts`가 표시창 없는 그림에는 null을 줌 → HUD의 옆 기둥). 표시창이 있는 그림을 다시 쓰게 되면 `deckPanels.json`에 `glass`만 적으면 예전처럼 창 위에 씁니다.
- **그림 전체가 어느 카메라에서나 보이게**: 그림을 키 줄 아래부터 화면 맨 아래까지 깝니다(`panelSpan`). 받침을 덜 보여 주는 카메라(SDVX · 강한 원근)에서는 그만큼 눌러 그리고, 그림 깊이의 1/4보다 더 누르지는 않습니다.
- **평면 카메라는 판정선이 조금 아래**(`config/camera.json`의 `PLANE.judgeLineY` 0.755, 나머지는 0.72): 평행 투영은 하단을 덜 깊게 보여 줘서, 같은 높이로는 그림이 끝난 뒤의 받침이 화면 아래에 드러났기 때문입니다.
- **콤보 · 판정 · 게이지의 높이는 기본 카메라 기준**: 다른 카메라에서도 화면에서 같은 높이, 게이지는 같은 길이로 보이게 트랙 위의 자리를 카메라마다 다시 구합니다(`likeCamera`, `HudPlane.like`).
- **하늘 스킨의 레인 덧그림**: 어느 카메라에서나 구름과 바람 궤적이 레인을 같은 비율로 채우게 그림의 줄을 카메라마다 옮겨 그립니다(`floorViewOf`, `FloorView`).
- **조명 자리**: 기어 조명이 비추는 그림 속 자리를 그림마다 재서 `deckArt.ts`의 `PANEL_MARKS`에 적었습니다: 기본의 조명 띠, 아쿠아 · 화이트 라인 · 별밤의 가운데 마크, 스틸의 파란 창(FEVER), 레드라인의 좌우 톱니 줄 둘(FEVER; 코드 그림에서는 왼쪽 점 무리 하나였고, 새 그림이 좌우 대칭이라 `gearLights.ts`에 오른쪽 조명을 하나 더함), 화이트 라인의 아래쪽 투영 빛(FEVER), 하늘과 파이어스타터의 FEVER 때 하단 전체의 옅은 빛. 그림에 없는 부품의 조명은 켜지지 않습니다(크리스털의 사파이어 판 셋, 하늘의 깃털). 키 줄의 조명은 모든 스킨이 그대로입니다.
- **파이어스타터의 키캡 문장**: 키캡마다 네 멤버의 문장을 왼쪽부터 차례로 하나씩 그립니다(`media/gears/fire/crests.png`, `deckArt.ts`의 `firePlate`).
- GPT 기어의 판정선 · 게이지 · 타격 효과는 사용자의 결정으로 청록 그대로입니다("청록으로 유지해줘").

알아 둘 점: 입체로 그린 물건(노브, 로켓, 홀로그램 등)은 기본 카메라 시점으로 그려져 있어 평면 카메라에서는 조금 기울어져 보입니다. 레드라인의 LED 도트는 기어가 좁게 보이는 약한 원근 · 평면 카메라에서는 뭉쳐서 선처럼 보입니다. 스틸의 레벨 미터와 레드라인의 전광판은 고정 그림입니다.

## RATE는 판정 글자 아래에 (2026-11-11)

사용자 요청: "RATE는 잘 안보이니까 판정 아래에 작게 표시하도록 위치를 변경해", "판정선 아래가 아니라 MAX 100% 같은 판정 아래에". RATE는 기어 하단과 왼쪽 열에서 빠지고, 트랙 가운데 판정 글자(와 FAST/SLOW · 오차 막대) 바로 아래에 작은 한 줄(라벨 11px · 숫자 17px, 720p 기준, 어두운 외곽선)로 항상 떠 있습니다(`Hud.ts`의 `RATE_NUM` · `RATE_LABEL` · `RATE_GAP`, `styles.css`의 `.hud-row.under-judge`). 기어 하단에는 SCORE와 SPEED만 남습니다.

## 스킨 고르기

설정 → 기어의 첫 줄 "스킨"(기본 / 크리스털 / 하늘 / 파이어스타터 / GPT / Gemini / Grok / Claude / 아쿠아 / 스틸 / 레드라인 / 화이트 라인 / 별밤)이 기어·노트·타격 효과를 함께 바꾸고 판정·콤보 글꼴을 "기어"로 돌려 놓습니다. 사이드 노트는 스킨에 들지 않으므로 고른 그대로 둡니다. 그 아래의 기어·판정·콤보 글꼴·타격 효과나 노트 탭의 노트를 따로 바꾸면 줄이 "직접 고름"으로 읽히고, 거기서 좌우로 한 번 움직이면 다시 스킨이 됩니다("직접 고름" 자체는 고르는 값이 아닙니다).

스킨은 따로 저장하는 값이 아니라 부품의 묶음입니다. 저장되는 것은 지금까지와 같은 부품 넷과 글꼴 출처이고, 줄은 그 값에서 스킨을 읽어 냅니다(`render/skins.ts`의 `SKIN_PARTS`, `skinOf`, `withSkin`). 그래서 예전 설정도 그대로 읽히고, 새 스킨은 `SKIN_IDS`·`SKIN_PARTS`와 이름(`ui/optionRows.tsx`의 `SKIN_NAMES`)에 한 줄씩 더하면 됩니다. 노트와 타격 효과 목록의 순서도 스킨 순서(기본, 크리스털, 하늘, 그 밖)로 맞췄습니다. 설정 화면(`ui/SettingsScreen.tsx`, `ui/optionRows.tsx`)은 세션 1 담당 파일이지만 사용자 지시로 고쳤습니다.

## 설정 기어 미리보기의 아래쪽 늘어짐 (기타 10)

원인은 설정 화면 배치가 아니라 렌더러였습니다. 그림으로 그리는 기어는 받침 그림보다 화면이 더 아래까지 보이면 그림의 **마지막 한 줄을 늘여** 채웠는데, 세로로 긴 미리보기에서는 그 구간이 길어 받침 아래가 늘어져 보였습니다(`deckArt.ts`의 `deckPicture`). 이제 그림 아래는 그림 깊이의 1/5 안에서 그림자로 가라앉습니다. 설정 화면 CSS는 건드리지 않았습니다.

## 플레이 중 그래픽 카드로 올라가는 것 (2026-11-13 측정)

"매번 같은 곳에서" 끊긴다는 말에 따라, 플레이 한 판 동안 WebGL로 넘어가는 것을 모두 세었습니다(텍스처를 만들고 지우는 것, 올린 바이트, 셰이더 프로그램, 드로 콜, 그리고 그래픽 프로세스의 메모리. 테스트 브라우저의 그래픽 카드는 소프트웨어라서 카드에 올라갈 것이 그 프로세스의 메모리로 보입니다). 채보는 67초짜리 7K+1S(단타 · 16분 연타와 동시치기 · 네 레인 롱노트, 카메라 큐 zoom · tilt · view · swing · dive를 최대값으로 네 마디마다), 1920×1080, 자동 플레이입니다.

- **새는 것은 없습니다.** 텍스처 수와 크기, 그래픽 프로세스의 메모리가 플레이 내내 일정합니다. 카메라 큐가 움직이거나 FEVER가 켜질 때 새로 만들어지는 것도 없습니다(큐가 움직이는 동안 다시 하는 것은 카메라와 기어 옆 그림의 변환뿐).
- **곡 중간에 올라가던 것**: 타격 효과의 사각형은 모자랄 때마다 하나씩 만들었는데, 사각형마다 시트의 사본(`texture.clone()`)을 쥐고 three.js는 사본을 만들 때 원본을 "바뀜"으로 표시합니다. 그래서 사각형이 하나 늘 때마다 **1536×1536 시트 한 장 전체(9.4MB와 밉맵)가 다시** 올라갔습니다. 사각형이 느는 때는 동시에 보이는 타격 효과가 그때까지의 최대를 넘는 때, 곧 노트가 가장 몰리는 구간이고, 같은 채보면 늘 같은 자리입니다. 여기에 롱노트의 효과 시트와 셰이더 프로그램 세 개가 첫 롱노트에서 처음 쓰이며 올라갔습니다.
- **고친 것**(`TrackRenderer`): 타격 효과의 사각형을 렌더러를 만들 때 레인마다 셋씩 미리 만듭니다(`primeHits`, `HITS_PER_LANE`. 효과 하나가 0.4초 이하라 사람이 치는 속도로는 다 쓰이지 않고, 다 쓰이면 가장 먼저 시작한 것이 자리를 내줍니다). 그리고 첫 프레임을 그리기 전에 트랙이 보여 줄 그림을 모두 올리고 프로그램을 모두 컴파일합니다(`warm`: 풀마다 하나씩 숨긴 채 만들어 그 종류가 장면에 있게 한 뒤 `renderer.initTexture` · `renderer.compile`). 그 뒤로는 곡 중간에 올라가는 큰 그림도, 컴파일되는 프로그램도 없습니다. 올린 양은 한 판에 84MB에서 30MB로 줄었습니다. 화면은 전과 같습니다.
- 소프트웨어 렌더러라 프레임 시간은 실제 PC와 다릅니다(표의 수는 모두 개수와 바이트입니다). 측정 스크립트는 저장소에 넣지 않았습니다.
