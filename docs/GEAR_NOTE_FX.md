## 타격 효과는 그림으로 그린 프레임 애니메이션 (2026-11-11)

사용자 의견(2026-11-11): 스킨 2 · Grok · Claude · GPT · 6 · 7 · 9 · 10 · 11의 이펙트가 "단순 도형 (원, 선)으로 이루어진 티가 너무 나고, 애니메이션도 너무 밋밋", "지속시간은 … 0.4초 이하가 이상적", "GEMINI API 우선으로 이미지 생성 방식으로 다시 작성", 후보에 없는 스킨도 코드 그림이면 이미지로. 그래서 **15개 스킨 모두** 타격 효과를 그림으로 바꿨습니다. 아래 스킨별 절의 "타격 효과" 설명 가운데 코드 그림(도형)의 묘사는 그림이 없을 때 나오는 대역(`tintArt.ts`의 `SKIN_HITS`)의 것입니다.

- 효과마다 Gemini가 **16프레임(4×4)의 프레임별 애니메이션 시트**를 그립니다: 치는 순간 한 장, 롱노트를 누르는 동안(반복) 한 장. 프레임마다 다른 그림이라 불꽃이 갈라지고 파편이 돌며 흩어집니다.
- 치는 순간은 **0.32초**에 끝납니다(프레임 9~12장을 28~37fps로). 거의 빈 첫 프레임은 빼서 키를 누르는 순간 섬광이 바로 보입니다. 누르는 동안은 24fps 반복입니다.
- 스킨의 효과는 제 색 그대로 화면에 더하고(매니페스트 `plain`), 기본 스킨의 플래시만 흰빛에 레인 색을 입힙니다.
- 이름이 바뀐 것: 파이어스타터 "불똥" → "불꽃", GPT "입력 중 점" → "물방울 왕관", Grok "펜 엑스" → "엑스 섬광"(굵은 획과 가는 획이 엇갈린 X가 번쩍이고 깨져 흩어짐), Claude "손 빛살" → "붓 빛살", 화이트 라인 "선 고리" → "선 불꽃".

| 스킨 | 치는 순간 | 누르는 동안 |
|---|---|---|
| 기본 "플래시" | 별 모양 섬광 → 전기가 튀는 충격파 고리 → 가는 호와 반짝임 | 흰 심지 둘레에 전기 줄기 |
| 크리스털 "크리스털 분광" | 마름모 섬광 → 무지개 변이 난 수정 조각이 사방으로 깨져 날아감 | 마름모 빛과 분광 반짝임 |
| 하늘 "구름 깃털" | 햇살 → 구름 고리가 부풀며 흰 깃털이 날림 | 햇빛 공과 감도는 구름 |

| Gemini "반짝임" | 네 갈래 큰 별 → 파랑 · 보라 · 분홍의 작은 별들이 흩어져 깜빡임 | 깜빡이는 네 갈래 별 |
| Grok "엑스 섬광" | 두 획이 엇갈려 X가 되고 번쩍인 뒤 모난 조각으로 깨져 날아감(흑백) | 깜빡이는 작은 X |
| Claude "붓 빛살" | 테라코타 붓 자국이 해처럼 퍼지고 물감 점이 튐 | 들쭉날쭉 숨 쉬는 붓 빛살 |
| 아쿠아 "록온" | 육각 고리가 열리며 청록 플라스마와 분홍 파편 | 돌아가는 육각 고리와 심지 |
| 스틸 "십자 섬광" | 십자 플레어와 쇠 불똥, 가는 충격파 고리 | 용접 불빛과 튀는 불똥 |
| 무지개 "색종이" | 흰 터짐 → 색종이 · 리본 · 별이 사방으로 | 사탕색 점과 별이 톡톡 |

| 크림슨 "파편 섬광" | X자 베기 섬광 → 진홍 칼날 조각과 휘는 호 | 사방으로 찌르는 진홍 가시 |
| 화이트 라인 "선 불꽃" | 가는 흰 선으로 그린 불꽃놀이가 피었다 떨어짐 | 다시 그려지는 선 별 |
| 별밤 "별빛" | 금빛 별 → 별가루와 작은 별들이 흩어져 깜빡임 | 깜빡이는 금빛 별과 별가루 |

## 기어 하단은 그림 한 장: 표시창 · 날개 · 문장 (2026-11-11)

사용자 요청(2026-11-11): "판정선을 더 위로 올리고 기어 하단 영역 자체를 넓히라", 이어서 "확장된 기어 하단에 맞게 스킨마다 하단 영역 이미지를 새로 생성해서 적용해줘 … 하단 영역이 여유가 있어지니까 컨셉에 맞는 디자인, 꾸밈 요소를 더 넣을 수 있겠지?". 그래서 15개 스킨 모두 **키 줄 아래의 받침이 Gemini가 그린 그림 한 장**입니다. 아래 스킨별 절의 "받침" · "수치" 설명 가운데 키 줄 아래의 묘사는 그림을 못 읽었을 때 나오는 코드 그림의 것입니다.

- **판정선**: 화면 높이의 72%(77%에서 올림). 기어 하단이 화면의 28%를 차지합니다(`config/camera.json`의 `judgeLineY`, 프리셋 네 개를 함께 맞춤).
- **구성**(그림 21:9, 위에서 내려다본 평면): 위쪽 가운데에 넓고 어두운 **표시창**(폭의 절반 남짓), 양옆 **날개**에 컨셉 장식(기본: 스피커 그릴 · 노브 · 하늘색 빛줄 / 크리스털: 수정 날개와 사파이어 / 하늘: 뭉게구름과 깃털 / 파이어스타터: 검은 칼날 무늬와 크롬 스피커 / GPT: 대화 말풍선 줄 / Gemini: 오로라와 네 갈래 별 / Grok: 궤도와 별자리 / Claude: 손그림 낙서 / 아쿠아: 흰 장갑판과 청록 통풍구 / 스틸: 깎은 패널과 파란 슬롯 / 무지개: 사탕 캡슐과 스프링클 / 레드라인: 빨간 사선 띠와 망점 / 크림슨: 진홍 빛줄의 장갑 / 화이트 라인: 선 도면 / 별밤: 별자리와 달의 위상), 표시창 바로 아래에 큰 **문장**(조그 휠, 수정 메달, 날개 문장, 불꽃 방패, 꽃 매듭, 별 원반, 블랙홀, 해 도장, 리액터, 기계 원반, 무지개 돔, 과녁, 칼날 문장, 얼굴 고리, 날개 별).
- **수치**: SCORE(위, 크게)와 SPEED(아래, 가운데)를 표시창 유리 위에 두 줄로 씁니다. 표시창은 모든 스킨이 어두운 유리라 글자는 밝은색입니다(GPT · Claude · 무지개도 표시창 위에서는 흰 글자). RATE는 판정 글자 아래로 갔습니다(아래 절).
- **카메라별로 보이는 범위**: 기본(SDVX)은 그림의 위쪽 45%쯤, 즉 표시창과 날개, 문장의 윗부분이 화면 아래에 걸쳐 보입니다. 약한 원근 · 평면은 문장 전체와 몸통까지 보입니다. 강한 원근(LOW)은 표시창까지만 보이고 두 줄을 보이는 만큼에 맞춰 씁니다.
- **키 줄**은 레인을 따라야 하므로 그대로 코드로 그립니다(누르면 켜지는 키캡 포함). 기어의 조명 가운데 키 줄의 빛은 그대로이고, 문장 자리 조명(`emblem`)은 그림의 문장에 맞춰 켜집니다.

## RATE는 판정 글자 아래에 (2026-11-11)

사용자 요청: "RATE는 잘 안보이니까 판정 아래에 작게 표시하도록 위치를 변경해", "판정선 아래가 아니라 MAX 100% 같은 판정 아래에". RATE는 기어 하단과 왼쪽 열에서 빠지고, 트랙 가운데 판정 글자(와 FAST/SLOW · 오차 막대) 바로 아래에 작은 한 줄(라벨 11px · 숫자 17px, 720p 기준, 어두운 외곽선)로 항상 떠 있습니다(`Hud.ts`의 `RATE_NUM` · `RATE_LABEL` · `RATE_GAP`, `styles.css`의 `.hud-row.under-judge`). 기어 하단에는 SCORE와 SPEED만 남습니다.

## 스킨 고르기

설정 → 기어의 첫 줄 "스킨"(기본 / 크리스털 / 하늘 / 파이어스타터 / GPT / Gemini / Grok / Claude / 아쿠아 / 스틸 / 무지개 / 레드라인 / 크림슨 / 화이트 라인 / 별밤)이 기어·노트·타격 효과를 함께 바꾸고 판정·콤보 글꼴을 "기어"로 돌려 놓습니다. 사이드 노트는 스킨에 들지 않으므로 고른 그대로 둡니다. 그 아래의 기어·판정·콤보 글꼴·타격 효과나 노트 탭의 노트를 따로 바꾸면 줄이 "직접 고름"으로 읽히고, 거기서 좌우로 한 번 움직이면 다시 스킨이 됩니다("직접 고름" 자체는 고르는 값이 아닙니다).

스킨은 따로 저장하는 값이 아니라 부품의 묶음입니다. 저장되는 것은 지금까지와 같은 부품 넷과 글꼴 출처이고, 줄은 그 값에서 스킨을 읽어 냅니다(`render/skins.ts`의 `SKIN_PARTS`, `skinOf`, `withSkin`). 그래서 예전 설정도 그대로 읽히고, 새 스킨은 `SKIN_IDS`·`SKIN_PARTS`와 이름(`ui/optionRows.tsx`의 `SKIN_NAMES`)에 한 줄씩 더하면 됩니다. 노트와 타격 효과 목록의 순서도 스킨 순서(기본, 크리스털, 하늘, 그 밖)로 맞췄습니다. 설정 화면(`ui/SettingsScreen.tsx`, `ui/optionRows.tsx`)은 세션 1 담당 파일이지만 사용자 지시로 고쳤습니다.

### 기어 양옆의 그림

사용자 지시: "firestarter 멤버들이 기어 양 옆에 서있도록", "조금 더 작게, 기어에 붙여", "4명 모두", 그리고 스킨 일러스트를 쓴 판으로 여러 번 다듬은 끝에 "이대로 진행해도 될거같아"(H 판). 처음에는 저장소가 공개라서 그림을 싣지 않고 플레이어가 자기 PC에서 고르게 했으나, 사용자가 "firestarter랑 ai들 그림은 기본적으로 들어가게", "플레이어가 고른 그림은 필요 없이 내가 올린 그림들을 고정으로" 빌드하라고 정했습니다(2026-11-11). 그래서 그림은 **빌드에 들어 있고**(`client/public/stage/fire/`), 설정에서 고르는 줄은 없습니다. 누구의 그림인지는 `client/public/licenses/STAGE-PICTURES.md`에 적었습니다.

- 그림은 `client/public/stage/<기어>/`에 있고 `client/public/stage/index.json`이 기어마다 파일 이름을 적습니다. 이름 순서대로 화면 왼쪽부터 섭니다.
- 파이어스타터는 두 장(`1-left.webp`, `2-right.webp`): 일러스트를 두 조각으로 나눈 판으로, 한쪽에 한 장씩 그 옆을 채웁니다. 키는 화면 높이의 0.94, 엉덩이 높이에서 폭의 10분의 3이 기어 뒤에 있습니다. 그림 둘레의 투명한 여백이 크기와 기어와의 거리를 정합니다.

- 기어 옆에 자리가 없으면(좁은 창, 넓은 레인, 설정의 미리보기) 서지 않습니다. 그림 파일이 없는 빌드에서는 옆이 빈 채로 같은 스킨이 나옵니다.

## 설정 기어 미리보기의 아래쪽 늘어짐 (기타 10)

원인은 설정 화면 배치가 아니라 렌더러였습니다. 그림으로 그리는 기어는 받침 그림보다 화면이 더 아래까지 보이면 그림의 **마지막 한 줄을 늘여** 채웠는데, 세로로 긴 미리보기에서는 그 구간이 길어 받침 아래가 늘어져 보였습니다(`deckArt.ts`의 `deckPicture`). 이제 그림 아래는 그림 깊이의 1/5 안에서 그림자로 가라앉습니다. 설정 화면 CSS는 건드리지 않았습니다.

## 검사

- `npx tsc --noEmit -p .` 통과, `npx vitest run` 498개 통과(GPT·Gemini·Grok·Claude 스킨까지).
- e2e: `e2e/phase3.spec.ts`와 `e2e/hud.spec.ts` 19개 중 16개 통과(스킨 줄을 넣기 전). 크리스털 부품을 골라 플레이하는 테스트(글자의 겹, 받침 수치의 자리, 라벨 색까지 확인)를 포함합니다. 스킨 줄을 넣은 뒤에는 그 줄의 테스트(스킨 하나로 부품과 글꼴이 함께 바뀜, 사이드 노트 유지, 직접 고름)와 부품 선택 테스트, `e2e/settings.spec.ts` 10개를 다시 돌려 모두 통과했습니다(그 가운데 기어 도움말 테스트는 기대값이 1차 구현 때부터 지금의 기어 순서·문구와 어긋나 있어 이번에 맞췄습니다). 실패한 3개("stem keysound…", "a YouTube link…", "a long intro is skipped…")는 이 작업 전의 커밋에서도 같은 자리에서 실패하는 것으로, 렌더러와 무관합니다(첫째는 앞서 확인했고, 나머지 둘은 이번에 브랜치를 시작한 커밋 b8747dc에서 직접 돌려 확인).
- 하늘 스킨: `e2e/phase3.spec.ts`와 `e2e/settings.spec.ts` 24개 중 22개 통과(스킨 줄이 세 스킨을 돌고, 하늘 스킨으로 플레이하면 글꼴·글자 채움·받침 수치·게이지 캡슐이 제 모양인지, 도움말이 하늘의 문구만 보여 주는지 확인). 실패 2개는 위의 스템·유튜브 테스트로 기준 커밋에서도 같습니다. 레인의 곡선은 시안과 게임 화면의 가는 선만 뽑아 겹쳐 보아 같은 자리를 지나는 것을 확인했습니다.
- 화면 확인: 7K+1S · 6K+FX(반쪽 덮기) · 4K(FEVER), 카메라 SDVX · FLAT · LOW · PLANE, 설정의 기어 미리보기. LOW 카메라처럼 받침이 화면에 조금만 보이면 수치판을 그리지 않고 수치는 예전처럼 기어 왼쪽에 나옵니다.
- 60fps: 이 환경은 소프트웨어 렌더러(SwiftShader)라 실제 PC의 프레임은 재지 못했습니다. 추가한 것은 프레임마다 그리는 양을 늘리지 않습니다(받침·키캡·효과 그림은 시작할 때 한 번 그리고, 글자의 겹은 글자가 바뀔 때만 다시 그립니다).

## 남은 것

- **이미 저장된 설정은 바뀌지 않습니다.** 예전 빌드로 실행한 적이 있는 PC는 저장된 기어·노트·효과를 유지합니다. 설정 → 기어 → 스킨에서 원하는 스킨을 고르면 됩니다.
- '하늘' 스킨에서 레인의 옅은 구름과 타격 효과의 구름·깃털은 코드로 그린 모양입니다. 기본·크리스털 스킨의 받침도 하늘 스킨처럼 Gemini로 뽑은 그림을 깔 수 있습니다(지금은 전부 코드).
- 레인 그림의 세 가닥은 기본 카메라(SDVX)의 원근에 맞춘 것입니다. 다른 카메라에서는 같은 트랙 위 자리를 지나되 화면에서의 모양은 그 카메라대로 보입니다.
- '기본' 스킨의 콤보·판정 글꼴은 예전 그대로입니다(굵은 장체, 기울임 없음).
- 설정의 기어 미리보기에는 HUD가 없어 수치판·창이 빈 채로 보입니다.
- 사이드 레인을 따로 두는 설정(사이드 노트 "레인")에서는 그 레인의 노트와 롱노트도 스킨의 노트 모양으로 나옵니다. 건반 위에 깔리는 사이드 노트만 게임 공통 모양입니다.
- 판정 등급에 따라 타격 효과의 크기·색을 달리하는 것: 렌더러의 `hitEffect`가 등급을 받지 않아 `PlayController`를 함께 고쳐야 합니다.
- 타격 효과는 레인 폭의 1.8배 크기로 그려져(렌더러 공통) 가장자리 레인에서는 레일 밖으로 조금 나갑니다. 크리스털의 파편도 같습니다.
- 효과음: 만들지 않았습니다(ElevenLabs 등 유료 API는 사용 전 허락 필요).
- `README.md`와 `docs/ARCHITECTURE.md`·`docs/TESTING.md`의 기어·노트 설명과 `docs/screenshots/33-gear-standard.png`은 '기본' 스킨을 바꾸기 전 내용입니다(이 브랜치에서는 고치지 않았습니다. 합칠 때 함께 갱신해야 합니다).
- `e2e/screenshots.spec.ts`의 예전 테스트들은 `autoplayFor`가 지금 화면과 맞지 않아(Shift+Enter가 곧바로 플레이를 시작) 이 환경에서 돌지 않았습니다. '기본'과 크리스털 스킨 테스트만 돌렸습니다.
- 첫 커밋(567a61d) 메시지에 모델 이름이 든 줄이 남아 있습니다. 고치려면 force push가 필요해 그대로 두었습니다.
